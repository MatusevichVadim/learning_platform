# Система рейтинга (Rating System)

Документ описывает, как работает рейтинг пользователей в приложении: из каких
частей он состоит, по каким формулам считается и где хранится.

---

## 1. Где хранятся данные

В базе данных добавлены три колонки (миграция `backend/migrate_rating.py`):

| Таблица | Колонка        | Тип      | Назначение                                                                 |
|---------|----------------|----------|----------------------------------------------------------------------------|
| `tasks` | `rating`       | INTEGER  | Сложность/вес задания. Целое число от **1 до 5**. По умолчанию `1`.        |
| `users` | `rating`       | INTEGER  | **Вычисляемая** часть рейтинга (задачи + серии). По умолчанию `0`.        |
| `users` | `rating_bonus` | INTEGER  | Ручная корректировка администратора (бонус). По умолчанию `0`.            |

**Итоговый (эффективный) рейтинг**, который видит пользователь:

```
effective_rating = users.rating + users.rating_bonus
```

Поле `users.rating` заполняется автоматически и не редактируется вручную.
Поле `users.rating_bonus` администратор может менять вручную (вкладка
«Пользователи»), чтобы начислить баллы за активность вне платформы.

---

## 2. Рейтинг за задания (Task rating)

Каждое задание имеет свой рейтинг `task.rating` ∈ {1, 2, 3, 4, 5}.
Когда пользователь **впервые** правильно решает это задание, он получает
`task.rating` баллов.

> Повторное решение уже решённого задания баллы не приносит (чтобы нельзя было
> бесконечно «накручивать» рейтинг одним и тем же заданием).

Формула накопленных баллов за задания:

```
R_tasks = Σ over distinct correctly-solved tasks ( task.rating )
```

Администратор задаёт `task.rating` при **создании** и **редактировании** задания
(поле «Рейтинг задания», 1–5). Если администратор меняет рейтинг задания, рейтинг
всех пользователей, отправлявших это задание, пересчитывается автоматически.

---

## 3. Рейтинг за серию правильных решений (Streak bonus)

Рейтинг также начисляется за **решение задач подряд без ошибок**.

Определяется «серия» (streak) — количество подряд идущих правильных отправок
(submission с `is_correct = true`). Любая неправильная или ожидающая проверки
отправка **обнуляет** серию.

Когда серия достигает одного из контрольных значений, пользователь получает
бонус, равный этому значению:

| Серия подряд правильных решений | Бонус |
|---------------------------------|-------|
| 5                               | +5    |
| 10                              | +10   |
| 15                              | +15   |
| 20                              | +20   |

Бонус начисляется **ровно при достижении** контрольного значения (на 5-й, 10-й,
15-й и 20-й правильной отправке подряд). Если серия продолжается дальше (например,
21-я правильная отправка), новых бонусов нет, пока не появятся новые уровни.

Формула бонуса за серию:

```
R_streak = Σ over k ∈ {5, 10, 15, 20}, где streak достиг k:  k
```

Контрольные значения и размер бонуса заданы в `backend/app/rating.py`
(`STREAK_MILESTONES` и функция `streak_bonus`).

---

## 4. Итоговая формула

```
users.rating = R_tasks + R_streak
            = Σ(distinct solved task.rating) + Σ(streak_bonus)

effective_rating = users.rating + users.rating_bonus
```

Пример. Пользователь решил 3 разных задания с рейтингом 3, 2 и 5 (итого 10 баллов)
и при этом 7 раз подряд решал задания без ошибок (серия достигла 5 → +5 баллов,
затем сломалась). Тогда:

```
users.rating = (3 + 2 + 5) + 5 = 15
effective_rating = 15 + rating_bonus
```

---

## 5. Когда пересчитывается рейтинг

Функция пересчёта — `recompute_user_rating(db, user_id)` в `backend/app/rating.py`.
Она перебирает все отправки пользователя в хронологическом порядке и заново
считает `users.rating`. Вызывается автоматически:

1. После отправки решения (квиз или код) — `routers/public.py`.
2. После ручной проверки отправки администратором — `routers/admin.py`
   (`POST /admin/submissions/{id}/review`).
3. После изменения рейтинга задания администратором — пересчитываются все
   пользователи, отправлявшие это задание (`PUT /admin/tasks/{id}`).
4. Массово — эндпоинт `POST /api/admin/recompute-ratings` (например, после
   пакетного изменения заданий) или миграция `backend/migrate_rating.py`.

## 6. API

| Метод | Путь                          | Кому    | Описание                                                        |
|-------|--------------------------------|---------|-----------------------------------------------------------------|
| GET   | `/api/leaderboard`             | любой   | Список всех пользователей, отсортированный по `effective_rating` по убыванию (id, username, full_name, rating). |
| GET   | `/api/admin/users?sort_by=rating&order=desc` | admin | Список пользователей с сортировкой по рейтингу. |
| PUT   | `/api/admin/users/{id}`        | admin   | Поле `rating_bonus` — ручная корректировка рейтинга.            |
| POST  | `/api/admin/recompute-ratings` | admin   | Пересчитать рейтинг всех пользователей.                         |
| PUT   | `/api/admin/tasks/{id}`        | admin   | Поле `rating` (1–5) задания.                                    |
| POST  | `/api/admin/tasks`             | admin   | Поле `rating` (1–5) при создании задания.                       |

---

## 7. Лидерборд

Кнопка «Лидерборд» доступна всем авторизованным пользователям (и администратору,
и обычному пользователю). Она открывает страницу со списком пользователей:
ФИО (full_name, либо username, если ФИО не указано) и эффективный рейтинг,
отсортированный от большего к меньшему.
